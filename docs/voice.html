The esbuild voice

The voice: write release notes like esbuild

foghorn follows the release notes of esbuild. Evan Wallace writes them. This page lists the ten patterns that foghorn encodes, the three presets, and how well the checker agrees with the real releases. esbuild has not endorsed foghorn.

The ten patterns

1. A preface only for breaking releases

A bold line opens a breaking release. Pinning advice follows.

This release deliberately contains backwards-incompatible changes.

Source: esbuild v0.27.0

2. The title names the thing and the change

The title carries the issue links. A security entry links the advisory id.

Fix regression with --define and import.meta (#4010, #4012, #4013)

Source: esbuild v0.24.2

Restrict access to esbuild's development server (GHSA-67mh-4wv8-2f99)

Source: esbuild v0.25.0

3. Background, then old behavior, then the new behavior

The entry goes on with "With this release, these keywords will now be parsed correctly."

Previously esbuild could incorrectly fail to parse certain keywords as TypeScript tuple labels

Source: esbuild v0.25.5

4. Show, do not describe

Labeled blocks show Original code, Old output and New output, with the flags in the label.

// Old output (with --bundle --format=esm --platform=node --target=node18,es2022)

Source: esbuild v0.23.1

5. Say the cause and the version of a regression

Name the version where the change broke.

The regression was introduced in version 0.18.7 of esbuild.

Source: esbuild v0.23.1

6. Name new requirements concretely

Use a short list with the version numbers.

* macOS: now requires macOS 12 (Monterey) or later

Source: esbuild v0.27.0

7. A migration step, not an apology

Give the exact flag that restores the old behavior.

If you don't want this behavior, you can do --packages=bundle to allow packages to be included in the bundle

Source: esbuild v0.22.0

8. Credit by handle, in one sentence

Two forms: one for a report, one for a fix.

This fix was contributed by @sapphi-red.

Source: esbuild v0.24.2

Thanks to @sapphi-red for reporting this issue.

Source: esbuild v0.25.0

9. Plain honesty

A hedge marks real uncertainty. It is never filler.

Hopefully this release is uneventful

Source: esbuild v0.26.0

10. Size follows content

A release with one change has one entry. Version 0.26.0 is one entry of 678 characters. Version 0.24.2 is one entry of 712 characters. No padding.

The gap esbuild leaves

esbuild rarely says who a change affects. When a change can break someone, the default voice adds an optional Affects: line and a To check: line. The strict preset leaves them out.

Three presets

  • esbuild-plus is the default. It uses the first person. It has the esbuild shape plus the Affects: and To check: lines.
  • esbuild follows the esbuild shape, as far as ten hand-cut excerpts go. It uses the first person. It has no Affects: line.
  • neutral uses the third person. The project is the subject. Credits read "Reported by @x. Fixed by @y."

What a voice sets

A voice is a JSON file. These are its fields:

  • person: first or third.
  • creditStyle: esbuild, thanks or by-line.
  • creditOwner: false by default. foghorn credits only the people who wrote or reported a change. It leaves out the owner of the repository unless you set this to true.
  • prefaceRules: the bold line and the pinning advice of a breaking release.
  • exampleStyle: the three labels of an example.
  • affectsLine: whether an Affects: line is allowed.
  • maxEntryChars: 2500 for esbuild-plus and neutral, 3000 for esbuild.
  • openers and bannedWords: the opening phrases, and 16 marketing words that the checker warns about.

The severity map

A voice can change the level of any check. The esbuild preset turns one hard check into a warning.

{
  "severity": {
    "entry-no-link-or-credit": "warn"
  }
}

Honest numbers

We ran the checker on the 30 latest esbuild releases, v0.22.0 to v0.28.2.

  • Under the strict esbuild preset, 2 releases break a hard check: v0.28.0 and v0.25.6.
  • Under esbuild-plus, 8 releases break a hard check.

The gap is the link-or-credit check. Some of esbuild's own entries have neither. The strict preset makes that a warning. The default voice keeps it hard, because a reader of a release needs a place to look. That rule is ours. It is not esbuild's.

Two limits come from esbuild's own maxima in those 30 releases. The most examples in one entry is 4. The longest paragraph is 859 characters, so the checker warns above 900. A warning is advice. A hard check is a rule.
