Claude Code plugin

Release notes worth reading.

foghorn is a Claude Code plugin. It drafts release notes for a tag range. It follows the voice of esbuild's releases: technical, honest, and useful to the people a change affects. A checker fails notes that skip the facts a reader needs.

Before and after

Before is what GitHub wrote for the last release of typescript-patterns-enforcer. After is one entry from the foghorn draft for the next release. They are two different changes. The pair shows the shape of a note, not a rewrite.

Before
## What's Changed
* Keep the new gate rules from tripping the scanner themselves (v0.5.11) by @gagoar in https://github.com/gagoar/typescript-patterns-enforcer/pull/26


**Full Changelog**: https://github.com/gagoar/typescript-patterns-enforcer/compare/v0.5.10...v0.5.11

GitHub's --generate-notes names a pull request. It does not say what changed for you.

After

  • Stop the magic-number check from flagging numbers inside a named constant (#35)

    Previously the check flagged every number in an arithmetic expression, even when the expression is the initial value of a const that names the result. The check also flagged a number inside an as const table, although the table is the named constant.

    With this release, the check skips a number in the arithmetic of a const initializer and a number inside an as const literal. This is a deliberate difference from typescript-eslint, which exempts only a bare initializer.

    Original code:

    export const MAX_BYTES = 16 * 1024 * 1024;

    Old output:

    ts-patterns: 3 mechanical violation(s) in magic.ts:
  L1:26  no-magic-numbers  No magic number: 16.  → SKILL.md Core Rule 9 — extract to a named const
  L1:31  no-magic-numbers  No magic number: 1024.  → SKILL.md Core Rule 9 — extract to a named const
  L1:38  no-magic-numbers  No magic number: 1024.  → SKILL.md Core Rule 9 — extract to a named const

    New output: none. The hook exits with code 0.

foghorn says what the code did, what it does now, and shows the output.

The full run is on the showcase page.

Three commands

  • /foghorn:draft v1.2.0..v1.3.0 collects the changes of the range, drafts the notes, checks them and polishes them.
  • /foghorn:check RELEASE.md runs the checker on a file and explains each finding. It changes nothing.
  • /foghorn:voice shows, picks or edits the voice.

Install

Add the marketplace and install the plugin.

/plugin marketplace add gagoar/foghorn
/plugin install foghorn@foghorn

foghorn needs two other plugins for the prose step: unmistakable, which holds the asd-ste100 skill, and iceberg, which holds iceberg:edit. Both come from the gago-plugins marketplace.

/plugin marketplace add gagoar/gago-plugins
/plugin install unmistakable@gago-plugins
/plugin install iceberg@gago-plugins

How it differs from --generate-notes

gh release create --generate-notes is instant, free and deterministic. It lists pull request titles and authors. If your pull request titles are good and your readers only need a list, use it.

foghorn does more and costs more. It reads the diffs and the linked issues. It drops internal noise. It classifies the changes. It asks for a real before and after. It adds a preface to a breaking release. It checks the result with code.

It needs a model. It takes minutes. A person must read the draft before it ships. A model can still misread a diff.
