Claude Code plugin

Release notes worth reading.

foghorn is a release notes generator for Claude Code. It drafts technical release notes for a tag range. Each note says what changed for a user, shows the old and new output, says who is affected, and says how to check.

A foghorn is a loud signal that tells people what is ahead. The plugin is named for what release notes do.

Machines read release notes now, as well as people. A person still has to follow a note when an upgrade breaks something. foghorn writes the note so that both can.

/plugin marketplace add gagoar/gago-plugins
/plugin install foghorn@gago-plugins

A foghorn entry for the first of them

  • Check TypeScript files written through a shell with an advisory Stop hook (#33)

    The mechanical checks ran from a PostToolUse hook, and that hook only sees files that the Edit and Write tools wrote. A .ts file written by a shell heredoc or a script never reached the checks.

    With this release, the plugin also registers a Stop hook. When a session ends, it walks the working directory for .ts and .tsx files modified since the session began and runs the same checks on them. It skips node_modules, .git, dist, build, out, coverage, .next, .turbo and .d.ts files. It is advisory: it reports through systemMessage and always exits 0, so it cannot trap a session.

    New output (a .ts file written through a shell, then the session stops):

    ts-patterns: mechanical violations in TypeScript files changed this session (the edit hook does not see files written through a shell):
src/list.ts:
  L1:64  no-zero-comparison  `.length` compared with zero: coerce it (`!!x.length`, `!x.length`) (see SKILL.md Core Rule 10).

This entry says what the code did and what it does now. It shows the output. The full run is on the showcase page.

What a good release note does

A good release note says what changed for a user. A pull request title says what a developer did. A reader wants the other fact: what is different after I upgrade.

It shows the old output and the new output. "Improved error handling" sends the reader to the diff. Two blocks of output take five seconds to read. If the author cannot show the output, the note says so.

It says who is affected and how to check. Most changes touch nobody. A few break someone. For those, one line names the people and one line gives a command that tells them if they are one of them.

It credits the people who are not the maintainer. The person who reported the bug and the person who fixed it get their handles. And it admits what the author does not know. If a check matches only a narrow shape, the note says so. A hedge that marks a real doubt is content, not filler.

How it works

/foghorn:draft v1.2.0..v1.3.0 runs these steps:

  1. It reads git history, merged pull requests and linked issues. It uses read-only commands.
  2. It drops internal changes, such as docs-site work, CI and version bumps. It tells you how many.
  3. It sorts each change as breaking, security, feature or fix. It shows you the table, and you can change it.
  4. It writes each entry in the voice. A change of behavior gets a real before and after, read from the diff or run from the code. It never invents an example.
  5. It checks the draft with code, and it polishes the prose. A breaking release with no preface fails. So does a behavior change with no old and new output. So does an entry with no link and no credit.
  6. It prints the draft. You read it and you publish it. foghorn never publishes.

What it touches

  • It reads git history and GitHub with read-only commands.
  • The one script that starts a process is scripts/gh-read.ts. It allows a fixed list of read-only gh commands. It gives gh only a short list of environment variables, and it never prints the credential.
  • foghorn never publishes a release. You read the draft and you publish it.
  • MIT license. No account and no telemetry in the scripts.

Install and use

foghorn needs two other plugins for the prose step: unmistakable, which holds the asd-ste100 skill, and iceberg, which holds iceberg:edit. Both come from the same marketplace.

/plugin install unmistakable@gago-plugins
/plugin install iceberg@gago-plugins
  • /foghorn:draft v1.2.0..v1.3.0 collects the changes of the range, drafts the notes, checks them and polishes them.
  • /foghorn:check RELEASE.md runs the checker on a file and explains each finding. It changes nothing.
  • /foghorn:voice shows, picks or edits the voice.

Limits

foghorn needs a model. It takes minutes. A model can misread a diff, so a person must read every draft. The checker looks for an example. It cannot prove that the example is true. gh release create --generate-notes is instant and free. If your pull request titles are good and your readers need only a list, use it. foghorn is better than generate-notes only when your readers need more than a list.
